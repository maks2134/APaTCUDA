## 1. Что делает программа одной фразой

Перемножает две «большие» матрицы, где каждый элемент — не одно число, а **плитка 12×12 float**.

Считает результат двумя способами:

1. **C1** — обычные циклы (`matmul_auto`), компилятор может сам сделать SIMD  
2. **C2** — ручной SSE2 (`matmul_sse2`)

Потом сравнивает C1 и C2 и печатает время (на x86 — такты `rdtsc`).

```text
A (L×M блоков)  ×  B (M×N блоков)  →  C (L×N блоков)
каждый блок = 12×12 float
```

## 2. Мини-словарь Rust

| Конструкция | Что это |
|-------------|---------|
| `fn name(...) { }` | функция (как в C/Java) |
| `fn main()` | точка входа программы |
| `struct Name { ... }` | структура (как класс без методов) |
| `impl Name { ... }` | методы этой структуры |
| `pub` | публичное — видно из других модулей |
| `mod foo;` | подключить файл `foo.rs` как модуль |
| `use foo::Bar;` | импорт имени |
| `let x = ...;` | неизменяемая переменная |
| `let mut x = ...;` | изменяемая переменная |
| `&T` | ссылка «только читать» (borrow) |
| `&mut T` | ссылка «можно менять» |
| `Vec<T>` | динамический массив в куче |
| `f32` | float 32 бита (как `float` в C) |
| `usize` | целый размер/индекс (как `size_t`) |
| `u32` / `u64` | беззнаковые 32/64-бит целые |
| `Result<T, E>` | либо успех `Ok(T)`, либо ошибка `Err(E)` |
| `?` | «если Err — вернуть ошибку наверх» |
| `match` | ветвление по вариантам (как switch++) |
| `unsafe { ... }` | блок, где можно делать опасные вещи (указатели, SIMD) |
| `#[cfg(...)]` | код компилируется **только если** условие истинно |
| `#[inline]` | подсказка: желательно встроить функцию |
| `#[derive(Clone, Copy)]` | автогенерация копирования структуры |
| `for i in 0..N` | цикл i = 0,1,...,N-1 |
| `println!(...)` | печать в stdout |
| `eprintln!(...)` | печать в stderr |
| `crate::` | путь от корня текущего пакета |

**Владение (коротко):** у каждого значения один «хозяин». Когда хозяин уходит из области видимости — память освобождается. Ссылки `&` / `&mut` позволяют временно «одолжить» значение без копирования всей матрицы.

## 5. `src/matrix.rs` — данные

### Константа размера блока

```rust
pub const BLOCK: usize = 12;
```

Вариант лабы: плитка **12×12**. Число 12 делится на 4 → удобно для SSE2 (по 4 float в регистре `xmm`).

### Структура `Block`

```rust
#[repr(C, align(16))]
#[derive(Clone, Copy, Debug)]
pub struct Block {
    pub data: [[f32; BLOCK]; BLOCK],
}
```

- `data` — двумерный массив 12×12 float.  
- `align(16)` — адрес блока кратен 16 байтам (важно для SSE).  
- `repr(C)` — предсказуемый layout в памяти.  
- `Clone, Copy` — блок можно копировать как обычное значение (144 float = 576 байт).

### Методы `Block`

**`zeros()`** — блок из нулей (начальное значение C).

**`fill(value)`** — все элементы = одно число (для тестов).

**`mul_add_scalar(&mut self, a, b)`** — эталонное умножение блоков без SIMD:

```text
self += a * b
для i, k, j:
  self[i][j] += a[i][k] * b[k][j]
```

Транспонирования нет: `b` читается как `b[k][j]` (по строкам).

### Структура `BlockMatrix`

```rust
pub struct BlockMatrix {
    pub rows: usize,
    pub cols: usize,
    pub data: Vec<Block>,
}
```

Внешняя матрица: `rows × cols` **блоков**, все блоки лежат в одном `Vec` подряд (row-major):

```text
индекс блока (i, j) = i * cols + j
```

**`zeros(rows, cols)`** — матрица нулевых блоков.

**`from_seed(...)`** — заполняет матрицу «псевдослучайными» float из seed (детерминированно, чтобы на защите результат воспроизводился). Алгоритм: линейный конгруэнтный генератор → биты → число примерно в диапазоне [-0.5, 0.5].

**`get` / `get_mut`** — безопасный доступ с проверкой границ (в Debug).

**`get_unchecked` / `get_unchecked_mut`** — доступ **без** проверки границ (`unsafe`). В горячем цикле умножения это убирает лишние проверки и помогает компилятору оптимизировать/векторизовать. Безопасно только если индексы точно в пределах матрицы (в наших циклах так и есть).

## 6. `src/mul_auto.rs` — C1 (автовекторизация)

### Внешний цикл `matmul_auto`

```rust
pub fn matmul_auto(a: &BlockMatrix, b: &BlockMatrix) -> BlockMatrix
```

Принимает ссылки на A и B (не копирует целиком), возвращает новую матрицу C.

1. Проверка: `a.cols == b.rows` (иначе нельзя умножать).  
2. `l, m, n` — размеры в блоках.  
3. `c = zeros(l, n)`.  
4. Тройной цикл по блокам:

```text
для i = 0..L
  для k = 0..M
    для j = 0..N
      C[i,j] += A[i,k] * B[k,j]   // умножение двух 12×12
```

Это обычный алгоритм произведения матриц, только «элемент» = блок.

### Ядро `mul_add_block_auto`

```rust
#[inline(never)]
pub fn mul_add_block_auto(c, a, b) {
    for i in 0..12 {
        for k in 0..12 {
            let aik = a.data[i][k];
            for j in 0..12 {
                c.data[i][j] += aik * b.data[k][j];
            }
        }
    }
}
```

- `#[inline(never)]` — **не** встраивать функцию: в дизассемблере легче найти именно это ядро (`task asm`).  
- Внутренний цикл по `j` идёт по **непрерывной строке** float → LLVM в Release часто делает из него `mulps`/`addps` (автовекторизация).  
- С флагами novec (`-vectorize-loops=false`) тот же код остаётся скалярным (`mulss`).

Это и есть **C1** из задания.

## 7. `src/mul_sse2.rs` — C2 (ручной SSE2)

### Условие компиляции

```rust
#[cfg(target_arch = "x86_64")]
```

Код SSE2 попадает в бинарник **только на x86_64**.  
На ARM Mac нативная сборка вместо этого использует заглушку `panic!(...)` (поэтому на Mac для лабы нужен `task run-vec-x86` или Windows Intel).

### Intrinsics

```rust
use std::arch::x86_64::{
    __m128, _mm_set1_ps, _mm_loadu_ps, _mm_mul_ps, _mm_add_ps, _mm_storeu_ps
};
```

Это не «голый asm-файл», а **intrinsics**: функции, которые компилятор превращает в SSE2-инструкции.

| Intrinsic | Смысл | Инструкция |
|-----------|--------|------------|
| `__m128` | 4×float в регистре | xmm |
| `_mm_set1_ps(x)` | `[x,x,x,x]` | broadcast |
| `_mm_loadu_ps` | загрузить 4 float | movups |
| `_mm_mul_ps` | умножить 4 пары | **mulps** |
| `_mm_add_ps` | сложить 4 пары | **addps** |
| `_mm_storeu_ps` | записать 4 float | movups |

### Ядро `mul_add_block_sse2`

```text
для i, k:
  aik = [a[i][k], a[i][k], a[i][k], a[i][k]]
  для j0 = 0, 4, 8:          // три шага по ряду из 12
    c[i][j0..j0+3] += aik * b[k][j0..j0+3]
```

`step_by(4)` — шаг 4. Для ряда длины 12 получается ровно 3 итерации, без «хвоста».

`#[target_feature(enable = "sse2")]` — функция требует SSE2 (на x86_64 это всегда есть).

Внешний `matmul_sse2` — тот же тройной цикл по блокам, что у auto, только внутри вызывается SSE2-ядро.

## 8. `src/timing.rs` — замер времени

### `read_cycles()`

На **x86_64**:

```rust
unsafe { core::arch::x86_64::_rdtsc() }
```

Инструкция **RDTSC**: читает счётчик тактов CPU, результат как `u64` (в железе это пара регистров EDX:EAX — как в методичке).

На **не-x86** (ARM Mac для отладки): наносекунды от `Instant` — **не** для защиты, только чтобы программа хоть что-то мерила локально.

### `time_call(f)`

1. Запомнить wall-clock (`Instant`) и cycles.  
2. `compiler_fence` — чтобы компилятор не вынес работу `f` за пределы замера.  
3. Вызвать `f()` (например `matmul_auto`).  
4. Снова cycles и время.  
5. Вернуть структуру:

```rust
Timed { value, cycles, elapsed }
```

- `value` — результат функции (матрица C)  
- `cycles` — разница счётчиков  
- `elapsed` — секунды для удобства  

`cycles_label()` печатает `"cycles"` на x86 или `"ns"` на ARM.

## 9. `src/verify.rs` — сравнение C1 и C2

Задание: результаты должны **полностью совпадать** (фрагменты матрицы не печатать).

```rust
matrices_close(a, b, abs_tol) -> CompareReport
```

Проходит **все** float во всех блоках, считает максимальную абсолютную ошибку `|a-b|`.

- `ok` — ошибка ≤ допуска (`1e-4` по умолчанию)  
- `max_abs_err` — самая большая разница  

Для float точное битовое равенство не всегда возможно из‑за порядка сложений, поэтому допуск нормален. На защите говорите: «сравнили все элементы, max abs error …».

`blocks_close` — то же для одного блока (в тестах).

## 10. `src/main.rs` — точка входа

### Модули и импорты

```rust
mod matrix;
mod mul_auto;
...
use mul_auto::matmul_auto;
```

Подключает остальные файлы и нужные функции.

### Аргументы командной строки

Структура `Args`: `l, m, n`.  
Заполнение матриц и допуск сравнения зафиксированы в коде (`SEED = 42`, `TOL = 1e-4`).  
C2 на не-x86 пропускается автоматически.

`parse_args()` читает `--l 64 --m 64 --n 64` и т.п.  
`L/M/N` — **число блоков**, не размер в float.

Вспомогательная `parse_usize` берёт следующее слово после флага и парсит число; при ошибке возвращает `Err(String)`.

### `main` по шагам

1. Разобрать аргументы (или выйти с ошибкой).  
2. Создать матрицы A и B через `from_seed`.  
3. Напечатать одну строку: размер блока, внешние размеры, архитектура.  
4. Замерить **C1**: `time_call(|| matmul_auto(&a, &b))`.  
5. Если не x86_64 — написать `C2 sse2: skipped` и выйти.  
6. Иначе замерить **C2**: `matmul_sse2`.  
7. Сравнить матрицы → `match: yes/no`.  
8. Если не совпали — `exit(1)`.

Замыкание `|| matmul_auto(&a, &b)` — анонимная функция без аргументов: «вызови matmul_auto с этими a и b». Её передают в `time_call`.

`cfg!(not(target_arch = "x86_64"))` — проверка **на этапе компиляции**: на ARM ветка SSE2 просто не выполняется в `main` (и не нужна).

## 12. Как это связано с Task (`run-vec` / `run-novec`)

Код C1 **один и тот же**. Меняются флаги компилятора:

| Task | RUSTFLAGS (упрощённо) | Эффект на C1 |
|------|------------------------|--------------|
| `run-vec` | `-C opt-level=3 -C target-cpu=native` | LLVM может вставить `mulps` |
| `run-novec` | + `-vectorize-loops=false` … | цикл остаётся `mulss` |

C2 (intrinsics) в обеих сборках остаётся с `mulps` — вы сами написали SIMD.

## 13. Что говорить на защите (по коду)

1. «Данные — матрица блоков 12×12 float, выравнивание 16.»  
2. «C1 — тройной цикл + ядро `mul_add_block_auto` обычными float; автовекторизация зависит от флагов.»  
3. «C2 — то же снаружи, внутри `_mm_mul_ps` / `_mm_add_ps`, шаг 4 по колонкам.»  
4. «Транспонирования нет.»  
5. «Время — `_rdtsc` вокруг всего расчёта C1/C2.»  
6. «Сравниваем все элементы; печатаем только match и время, не куски матрицы.»
